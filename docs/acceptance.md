# 客户端验收

在专用测试私聊和群聊中执行以下检查。单元测试与 SDK 检查不能替代 QQ 客户端显示验证。

| 项目 | 操作 | 预期结果 |
| --- | --- | --- |
| 目录同步 | 设置 QQ 资源路径，执行 `/qqemoji sync` | 状态显示资源条目、收藏接口状态和当前策略 |
| QQ 原生表情 | 从目录选择原生表情，在私聊和群聊发送 | 出站为 `face`，名称与显示符合预期 |
| Unicode | 从目录选择 Unicode 条目并随附文字发送 | 字符与文字同条显示 |
| 收藏表情 | 收藏一个测试表情，同步后发送 | 出站带 `sub_type=1`，客户端按表情显示 |
| 收藏刷新 | 删除该收藏，再次发送其旧 ID | 发送被拒绝，不使用旧缓存资源 |
| 商城表情 | 回复原始商城消息执行学习，再发送 | 保留包 ID、表情 ID 和 key，出站为 `mface`，显示符合账号权限 |
| 账号与会话隔离 | 切换账号或会话查询学习记录 | 其他账号目录和其他会话学习记录不可用 |
| 消息布局 | 为原生、商城、收藏表情随附文字 | 先发文字，再独立发表情，顺序和文字内容正确 |
| 类型开关 | 分别关闭四类表情，搜索并尝试发送旧 ID | 对应类型不可搜索或发送 |
| Unicode 过滤 | 禁用 Unicode 后生成含组合 emoji 的非流式回复 | emoji 被过滤，普通文字和标点保留 |
| 优先级 | 调整优先级并搜索多类型候选 | 首选类型排在前面 |
| 禁止回退 | 关闭回退并搜索首选类型没有的表情 | AI 无可用候选；手动指令仍可使用其他已启用类型 |
| 部分发送 | 文字确认后使表情发送超时 | 返回文字确认 ID 和部分发送状态，不重复文字或自动重试 |
| 首条失败 | 使随附文字发送超时 | 不继续发送表情，不报告全部成功 |
| 原生参数 | 测试支持结果、动画或连击的原生表情 | 参数保留，效果符合当前 QQ/NapCat 版本 |
| 限频与重复调用 | 连续触发相同调用或超过次数限制 | 重复调用和超限发送被拦截 |

验收记录应保存在私有位置；公开问题报告应隐去账号、资源地址和商城 key。
